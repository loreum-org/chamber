Design notes

  1. One sentence tells you what to do. The header copy extends the app's queueHeaderCta (which stops at the first sentence) with the ready count, and the viewer's authority chain sits next to it, so it's clear which seat is acting and how it signs. When anything needs you, Needs my confirmation is the default filter. "All" is selected here only so every card state shows at once. Implements the queue half of I-14.
  2. The freshness chip and source labels are the only liveness signals. No WebSocket or block polling (I-19). The "0 RPC calls since load" counter makes I-11/I-21 visible in dev builds. When the indexer lags or stalls, this page shows the indexer states and never falls back to RPC.
  3. Cross-proposal effects are stated on the card they affect. Required confirmations are max(submit-time quorum, live quorum) (_requiredConfirmations), so the pending 5 → 6 seat change (quorum 1 + ⌊6 × 51 / 100⌋ = 4) would take #46 from ready to 3 of 4. The Grants Safe handover on Mar 18 comes from the migration's parallel run in the indexer (#262). Both appear on #46 because they change when it should execute, and both link to the page where the decision is made (Board, Migrate).
  4. The decode is the source of truth, not the title. The one-line decode comes from calldata the indexer stored from SubmitTransaction (proposal.data) and goes through the #260 decoder. The proposer's title is metadata, a claim. Chips always show target, function name plus selector, and value, so a mismatched title stands out. There's no getLogs or localStorage fallback (M-16 review note on proposalCalldata.ts).
  5. Risk classes extend classifyTransactionRisk. A self-call upgrade is high, and the badge says why in a single line. Gate calls are tagged "LORE supply" and show the quarterly budget inline (M-15, M-16). Messenger and bridge targets will also classify as high (P-30). "Unknown recipient" means an address the indexer hasn't seen as a director, a Chamber-owned Safe or a past recipient (#44).
  6. Deadlines are countdowns on the indexer head clock (I-10 useIndexerHead), capped by the 30-day max age (WalletTypes.DEFAULT_TRANSACTION_MAX_AGE). Proposers can set shorter deadlines with the P-28 presets. The gate template sets #47's deadline to gate op #3's expiry (Apr 2), so the proposal can't outlive the window it needs.
  7. The list never simulates on load. Simulating is an RPC call, so it runs only when someone clicks (#260 TxSimulationPanel). Results stay cached for the tab and show their block. #47's "reverts NotReady until Mar 19" is predicted from the indexed gate eta (M-14, I-25), so the list can warn without spending RPC. This keeps the route at 0 in the I-21 RPC budget.
  8. Confirmations show the authority chain. Each one shows seat → owner → signer: owner EOA, a Safe's threshold, a session key or the agent's policy account. Contract fact: submitTransaction* records the proposer's confirmation (WalletLib calls confirmTransaction), so kofi.eth's SUBMIT-only key counted as a confirmation on #46. The UI labels it "at submit · SUBMIT scope" instead of hiding it. Whether that should stay is a C-17 pre-freeze question. Naming follows P-9: these are session keys, not operators.
  9. Batch confirm uses confirmBatchTransactions through the new hooks in P-28. A high-risk item can join a batch, but the batch review must show its full decode, the implementation checks and a passing simulation before the wallet prompt. Ready proposals switch the bar to executeBatchTransactions, because the two calls can't be mixed.
  10. Cancel is a quorum vote, not a button. cancelTransaction records a vote and cancels once live cancel votes reach the current quorum. History shows the voters so an unknown-recipient cancel like #44 can be reviewed later (#261 compliance export).
  11. The composer has four templates. The gate template comes from M-16, the session-key template from #259, and every template gets the P-28 deadline field. Draft from a description only fills typed fields. The preview is decoded from the resulting calldata, and the prose is saved as metadata. Nobody signs natural language, per the review's "LLM compiles, humans sign calldata" rule. The review scheduled a full LLM intent compiler for Phase 3, so this helper is a small, flagged step toward it.
  12. The "Approve a session key" template is limited. Only the NFT's contract owner can call setDirectorOperator (Chamber.sol:356), and a Chamber proposal can't self-call it (allowlist at :732). A Safe-module call from inside executeTransaction doesn't work either: the Safe would call back into the Chamber while executeTransaction holds its reentrancy lock, and setDirectorOperator is also nonReentrant, so it reverts. #45 therefore called approveHash on the Treasury Agent's policy Safe, which lists this Chamber as a required signer for owner-level changes, and the Safe executed setDirectorOperator in a separate transaction. The agent's routine confirmations go through the Safe's mandate-checking policy module instead, so they don't need the board. That keeps the board, not the agent, in control of the agent's key. For other owners, the template opens Session keys to sign from the owner account (#259).
