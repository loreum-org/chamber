Rules the contract enforces

6
  1. EOA owners can't set keys. Only a contract owner (a Safe or policy account) can call setDirectorOperator. EOAs act directly.
  2. An NFT transfer switches the key off. A key is bound to the owner that set it, so a new owner starts with no key. The record isn't deleted: if the NFT returns to that owner before expiry, the key works again. Clear it before a transfer.
  3. Expiry and scope are required. The contract rejects an expiry that is 0 or in the past, and scope 0. Full access needs the explicit UNSCOPED value.
  4. Confirm and execute wait one block. A new key can submit, revoke and cancel right away, but can confirm or execute only from its live-at block.
  5. The seat still has to be seated. If the seat drops out of the top 5, the key is inert until it returns.

Choose a scope

Bits follow the Proposer preset. Choose Custom to change them.

SUBMIT · 1Submit transactions, including batches. Works immediately.
CONFIRM · 2Votes for the seat. A stolen key could push a transaction to quorum. Keep votes on the Safe.
EXECUTE · 4Executes transactions that already have quorum. Waits for the live-at block.
UPDATE_SEATS · 8Proposes, executes or cancels a seat-count change (7-day timelock). Never offered for agent seats.
REVOKE · 16Withdraws the seat's confirmation. Works immediately.
CANCEL · 32Votes to cancel a pending transaction. Works immediately.

Unscoped (0xFFFFFFFF) is not offered. If a key needs every power, the Safe should act itself.

Design notes

  1. Naming. The top nav keeps the existing label "Operators", but every string on the page says "session key", per the naming ADR and copy pass (P-8, P-9). "Operator" never means a relayer. Relayers, verifiers, guardians and watchers are separate roles and don't appear here. The page is viewed as a signer on kofi.eth's Safe because only contract-owned seats can hold keys. What an EOA owner like lena.eth sees is shown in the side column.
  2. Every seat in one list, with the authority chain on each row (seat → owner → key), including seats that can't have a key and the reason. Rows instead of a table give each chain a full line, and the same layout works at phone width. All rows come from chamber-indexer (directorOperator joined to boardSeat and membershipToken, I-6). Status (live, not yet live, expired, stale) is derived in the query from the indexer head, not from getDirectorOperator or useBlockNumber (I-15, I-10). Opening this page makes zero JSON-RPC calls (I-21).
  3. The 14-day limit is a proposed app default, not a contract rule (the contract only needs a future expiry). Both live keys predate it: #12's key has run 47 days since Feb 9 and the Treasury Agent's 21 days since Mar 9. The rows say so rather than hiding it, and renewals get the default. The live-at block is shown for every key, but the row says when it has no effect: it only delays confirm and execute, and #12's 0x31 scope has neither. CONFIRM and UPDATE_SEATS have dashed borders because they are the bits whose misuse changes outcomes. Open question for Chad: adopt the 14-day default?
  4. AI directors confirm only through a policy account. The agent key has SUBMIT, EXECUTE, REVOKE and CANCEL (0x35). Every vote is a transaction from the policy Safe. This follows the review's "AI agents are directors, not relayers" recommendation. The page does not claim on-chain enforcement: the review puts "an agent director account with enforced mandates" in Phase 3, so in Phase 1 the mandate is checked by the policy Safe's co-signers and published in metadataURI. The live wizard's whitelist, value limits and time window live in localStorage (app/src/lib/operatorPolicy.ts) and are only checked by the app, so this mock drops them rather than show them as protection. Recent actions match the queue: kofi.eth submitted #46 with its key, the agent confirmed it at 15:20, and #44 was cancelled by #7, #44 and #58. #45 is shown the way the queue page records it: the board co-signed with approveHash, because a Chamber tx that calls back into setDirectorOperator would hit the reentrancy lock.
  5. ERC-8004 is display only. The review notes ERC-8004 is a draft and not a security primitive. The badge is info-colored, not accent, and the copy says the Chamber never checks it. The ways humans demote the agent sit next to the identity. A kofi.eth signer can't clear the agent's key, so the page says so instead of offering a button that would fail.
  6. The rules are stated in terms of what the contract does (Chamber.sol setDirectorOperator: rejects EOA owners, a zero or past expiry and scope 0, and sets liveAt = block + SEATING_DELAY). They are not framed as best practices. A transfer doesn't delete the session record; _isLiveSessionKey just stops matching the new owner, so a transfer back revives an unexpired key. "The move keeps the delegated weight on #44" holds because delegations are keyed to the tokenId. The one-block wait comes from BoardLib.syncSeatingControl, which resets the seating clock when the owner changes. Open confirmations stop counting because confirmOwner no longer matches (PMN-H01), which is why the EOA card warns about #46.
  7. The wizard follows the #259 pattern: pick a seat, pick a key, choose a scope preset, set expiry, then review decoded calldata. It improves on the live wizard in four ways. EOA-owned seats are shown disabled with the reason, instead of failing at the end. The presets (Proposer 0x31, Agent executor 0x35) replace a raw bitmask. UNSCOPED is never offered, and UPDATE_SEATS is locked for agent seats. The review step reuses the #260 decoder and simulation gate; the calldata is the real ABI encoding (selector 0xd7d5a6e3). Reading the Safe's owners, the key's code check and "Simulated at block 27,184,302 via RPC just now" are the only RPC on this page, and all of them happen inside the write flow. The Safe tx hash is shown for comparison on the signing device, as in the M-10 preflight.
  8. Destructive action = ghost danger button plus a typed phrase. Clearing a key is safe for the Chamber but surprising for a seat that relies on it. The box shows the authority chain it changes, names the exact call, and the button says what happens when you press it.
