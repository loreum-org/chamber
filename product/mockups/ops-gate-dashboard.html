Design notes

  1. Internal, and a snapshot rather than a live page. The P-6 review dropped a live /internal/gate route in favor of app/scripts/phase2-gate.ts, which writes snapshots/YYYY-Www.{json,md}. This mock shows that snapshot rendered in the app shell for the P-7 review. The freshness chip shows the pinned indexer block instead of "Indexed N s ago", because the numbers are fixed on purpose. The "Internal" label replaces the chamber header, no top-nav item is selected, and the wallet chip reads "Not connected" because nothing here is signed.
  2. The verdict comes first, with its margin next to it. Criterion 1 passes with zero slack, so the page says so and names the orgs that could flip it. The GO scope is stated in plan terms (P-7: GO moves P-22 to P-27 to ready). It says Chamber.sol stays unchanged and that spoke actions still start as home-chain quorum proposals, per the review's recommended design. The kill date is labelled as what P-4 asks for, "the latest date by which the gate can still pass", and it is relative to go-live, as the plan's risk section recommends. A fixed "end of Q1 2027" date could not be met with mainnet in late January. The date (16 weeks) is a proposed value for Chad to confirm.
  3. Every criterion names its evidence: an indexer table and column, or "manual". This is the P-4 acceptance rule. The audit and bounty rows use the placeholder line format, because this mock must not claim a real audit.
  4. Sparklines show the 8-week streak per org. They use one hue for counts and a red stub for a missed week, with the counts in the tooltip, the ARIA label, and a table view. The weeks are ISO W09–W16 (Mar 1 – Apr 25, 2027), the last 8 complete weeks before the review. Independent-director counts show why a number is lower than the seat count (team list, multi-seat owner). The bridge-template column is there because the P-6 acceptance lists bridge-template executions in the snapshot. It is labelled as a demand signal so nobody reads it as a sixth criterion.
  5. Interviews appear only as aggregates. The repo is public, and P-2 keeps per-interview rows in a private store. The snapshot never links an interviewee to one of the named orgs above. The counts (7 multi-chain, 5 asked, 5 both) come from manual.json. These answer the review's finding that there was "no customer evidence".
  6. Anti-gaming rules are visible. The review warned that metrics like "100+ transactions" and "5 operators" are easy to game. This panel shows what was removed and why: no-ops, the minimum value, self-dealing, multi-seat dedupe. Loreum's own chambers, including the Loreum Grants Chamber from the Safe migration, are excluded by the team list.
  7. Reproducible and tamper-evident. The snapshot pins the indexer block and prints the exact command and its hash. A test stubs fetch and asserts no eth_* calls, per the standing rule that display data comes only from chamber-indexer (P-6, I-21). The existing #261 compliance dashboard polls getLogs and is not reused.
